🛑 PRE-RESPONSE CHECKLIST
PHASE 1: INPUT FILTER (Data & Logic)
* [ ] Neutralize Tone: Remove "I feel," "I think," "Unfortunately," or "Sorry." Replace with "Current status," "Logs show," or "Analysis indicates."
* [ ] Data Integrity: Do I have the timestamp, error code, or screenshot to back this up? If no, finding the data is the first step.
* [ ] Binary Validation: Is my statement True or False? Remove all ambiguity (e.g., "It should work" → "It is currently functioning/not functioning").
PHASE 2: PROCESSING (Ownership)
* [ ] The "Why" Check: Am I just answering the question (Executor) or solving the root problem (Owner)?
* [ ] Impact Analysis: Does this action affect other systems? If yes, state it explicitly.
* [ ] Risk Ownership: If I am executing a risky command from someone else, have I documented their instruction? ("Proceeding as directed by [Name] despite noted risk.")
PHASE 3: OUTPUT (Communication)
* [ ] BLUF (Bottom Line Up Front): The Answer/Solution comes first. The explanation comes second.
* [ ] Definitive Next Step: Who does what, by exactly when? (e.g., "I will update you by 14:00 EST.")
* [ ] Professional Distance: Am I defending my ego, or stating the system state? (Detach self from the error.)
⚡ QUICK REFERENCE: "EXECUTOR" vs. "OWNER"
| Instead of saying... | Say this (System Mode) |
|---|---|
| "I'll try to fix it." | "I am investigating the root cause. Next update at [Time]." |
| "I think it's a network issue." | "Latency logs indicate packet loss at the gateway. Escalating to Network Team." |
| "Sorry for the delay." | "Analysis took longer than expected due to [Reason]. Current status is..." |
| "What should I do?" | "Based on the data, I recommend Option A because [Logic]. Shall I proceed?" |
